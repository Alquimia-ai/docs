Model Connections tell agents which model to use, where it is hosted, and how to authenticate. Each entry is reusable across multiple agents in your workspace.

{/* screenshot: settings-models-list */}

## Adding a model connection

Click **Add Model Connection** and fill in the form:

{/* screenshot: add-model-modal */}

| Field | Description |
|-------|-------------|
| **Name** | A friendly name shown in the agent builder (e.g., "GPT-4o Production", "Claude Sonnet Production") |
| **Connection type** | Where the model is hosted — OpenAI, Anthropic, Google Gemini, Groq, Ollama, OpenShift AI, Hugging Face, or Custom endpoint |
| **Model ID** | The identifier your provider expects (e.g., `gpt-4o`, `claude-sonnet-4-20250514`, `meta-llama/Llama-3.1-8B-Instruct`) |
| **Endpoint** | Shown based on connection type — custom URL for OpenShift or self-hosted servers; optional for Hugging Face dedicated endpoints. Always stored as a secret |
| **Credentials** | Which [secret](/core-concepts/secrets) holds the API key, and where its value lives — never the value itself |

Studio configures the technical connection for you. You choose where the model lives; agents reference the connection by name.

## Connection types

| Connection type | When to use | Example Model IDs |
|-----------------|-------------|-------------------|
| **OpenAI** | OpenAI or OpenAI-compatible cloud APIs | `gpt-4o`, `gpt-4o-mini` |
| **Anthropic** | Claude models | `claude-sonnet-4-20250514`, `claude-3-5-haiku-20241022` |
| **Google Gemini** | Gemini models | `gemini-2.5-flash`, `gemini-2.5-pro` |
| **Groq** | Groq-hosted models | `llama-3.3-70b-versatile`, `mixtral-8x7b-32768` |
| **Ollama** | A local or self-hosted Ollama server | `llama3.2:3b`, `qwen2.5:7b` |
| **OpenShift AI** | Models served in your OpenShift cluster | `llama-3-8b-instruct`, `mistral-7b-instruct` |
| **Hugging Face** | Dedicated Inference Endpoints or Hub repo IDs | `meta-llama/Llama-3.1-8B-Instruct` |
| **Custom endpoint** | vLLM, TGI, LM Studio, or other self-hosted servers | `llama-3`, `mistral-7b` |

<Tip>
  For Ollama, choose **Ollama** and enter the server address without `/v1` (e.g., `http://localhost:11434`). The API key is optional. For other self-hosted OpenAI-compatible servers (vLLM, TGI), choose **Custom endpoint** and set the full base URL.
</Tip>

Anthropic, Google Gemini and Ollama run on their own connectors, not through the OpenAI API, so their parameters follow each provider's own names. For example, Ollama limits the response length with `num_predict` rather than `max_tokens`.

## Credentials are references

A model connection names the secret its API key is read from and, with a custom endpoint, the
one its base URL is read from. **Endpoints are always secrets**: the agent spec carries only a
reference, never the URL. The connection itself never holds a value; the vault does.

Each secret field works one of two ways:

- **Use existing** — reference a secret the workspace already has. It is used as it is: the form
  shows where its value lives but does not change its definition or its value. Manage those under
  [Secrets](/platform/security#secrets).
- **New secret** — define one here:

| Field | What it decides |
|-------|-----------------|
| **Name** | The key the connection reads. `RESPONSE_PROVIDER_API_KEY` (and `RESPONSE_PROVIDER_BASE_URL`) are the platform defaults. A name already defined in the workspace is refused: pick it with **Use existing** instead. |
| **Value lives** | **Workspace** — one value every agent shares. **Agent** — each agent using the model holds its own. **Deployment** — one value for every workspace of the runtime. |
| **User scoped secret** | Each user stores their own value under [My credentials](/platform/security#my-credentials); their chats use it, never someone else's. |
| **Value** | Required for a **Workspace** or **Deployment** secret without per-user values: it has one value, so you set it right here. |

A platform default key keeps the platform's definition, so **Value lives** is fixed for it.

A model saved with its URL in plain text moves it into a secret the next time you save it; the form
prefills the URL as the new secret's value.
Saving registers the definition; changing **Value lives** or **Per-user values** of an existing
key re-defines it for everything that reads it, and values stored under the previous setting
stop being read.

Any other value is set where it belongs:

- an **Agent** value in that agent's **Secrets** section, or under [Secrets](/platform/security#secrets),
- your own value under [My credentials](/platform/security#my-credentials),
- or when [Try Me](/core-concepts/secrets#setting-values-while-trying-an-agent) asks for it.

<Warning>
  Every model reads `RESPONSE_PROVIDER_API_KEY` by default, and a workspace secret holds one value.
  When another model of a **different provider** already reads the key, the form warns you and
  suggests a key of the provider's own (for example `ANTHROPIC_API_KEY`), so each provider keeps
  its own value.
</Warning>

**To rotate a key**: set its new value under **Secrets**. Every agent
using the connection picks it up. Pointing a connection at another key leaves the previous one in
place; delete it under **Secrets** once nothing uses it.

## Headers that hold credentials

The runtime never returns a value that looks like a credential. A header such as
`Authorization` comes back hidden, so when you edit the connection its value field is empty
and reads **Stored value hidden — enter it again**. Enter the value again, or remove the
header, before saving. Studio does not save a connection while a hidden value is still empty.

To avoid re-entering it on every edit, keep credentials in the API key, which is stored as a
secret and survives edits unchanged.

## Endpoint guidance

| Connection type | Endpoint behavior |
|-----------------|-------------------|
| **OpenAI** | Default endpoint works for api.openai.com; use custom URL only for proxies or gateways |
| **Anthropic** | Endpoint is configured automatically |
| **Google Gemini** | Endpoint is configured automatically |
| **Groq** | Default Groq endpoint is used automatically |
| **Ollama** | Required. Address of the Ollama server, without `/v1` |
| **OpenShift AI** | Base URL of your model's inference route in the cluster (usually ending in `/v1`) |
| **Hugging Face** | Required for dedicated Inference Endpoints; leave empty for serverless Hub models using `org/model` IDs |
| **Custom endpoint** | Full base URL of your server (e.g., `http://localhost:8000/v1`) |

## Reasoning from self-hosted models

Some OpenAI-compatible servers return the model's reasoning in a field the standard OpenAI response doesn't have, such as `reasoning_content`. vLLM with a reasoning parser, DeepSeek-R1 and Kimi all do this. **Custom endpoint** and **OpenShift AI** connections keep that reasoning between turns automatically.

<Note>
  An **OpenAI** connection pointed at a custom URL does not keep it. If your server returns reasoning this way, use **Custom endpoint** instead.
</Note>

## Using connections in agents

When creating or editing an agent, select an existing model connection from the inference tab. You do not re-enter credentials — agents inherit authentication from the connection.

Agents and sentinels reference the connection rather than copying it, so editing it (model ID,
endpoint, headers, key) reaches all of them without saving them again. A connection that an
agent or sentinel still uses cannot be deleted: Studio lists who uses it.

## Using connections in TrustLens

TrustLens uses the same model connections for its Judge and Guardian roles. Configure the provider, model ID, endpoint, and credential once in **Model Connections**, then select that connection in the **TrustLens** settings tab.

Updating or rotating a model connection keeps credential management in one place. TrustLens supports OpenAI, Groq, and OpenAI-compatible custom connections.
