**Inference** selects which model connection the agent uses and lets you fine-tune its behavior with model parameters.

{/* screenshot: agent-creation-inference-tab */}

## Model connection

The **Model connection** dropdown lists all connections registered under [Models](/platform/settings/models). Select the one this agent should use — credentials are inherited from the connection; you do not re-enter API keys here.

Each option shows the connection name, type, and model ID (e.g., **GPT-4o Production — OpenAI** with `gpt-4o` below).

Different agents in the same workspace can use different connections. Common patterns:

- Use a powerful model (e.g., Claude Sonnet, GPT-4o) for complex reasoning agents
- Use a fast, cheap model (e.g., Groq Llama, Claude Haiku) for simple classification or routing agents
- Use a custom endpoint for local development and testing

<Warning>
  If the dropdown is empty, no model connections have been configured yet. Go to [Models](/platform/settings/models) and add at least one.
</Warning>

## Model parameters

Model parameters are optional key-value pairs passed to the LLM at inference time. They let you tune the model's behavior per-agent without changing the connection itself.

{/* screenshot: model-parameters-form */}

Common parameters:

| Parameter | Type | Description |
|-----------|------|-------------|
| `temperature` | float (0.0–2.0) | Creativity vs. determinism. `0` = highly deterministic, `1+` = more creative |
| `max_tokens` | integer | Maximum number of tokens in the response |
| `top_p` | float (0.0–1.0) | Nucleus sampling. Alternative to temperature for controlling randomness |
| `top_k` | integer | Limits sampling to the top K most likely tokens |
| `frequency_penalty` | float | Reduces repetition of frequently used words |
| `presence_penalty` | float | Encourages the model to introduce new topics |

### Parameters the provider does not define

The runtime checks model parameters against the provider's own list. It checks them when you save the agent, and again every time the agent answers. Studio sends each parameter you add as follows:

- **The provider defines it:** it is sent as-is.
- **The provider does not define it** (`top_k`, `frequency_penalty` and `seed` on OpenAI, for example): it is sent inside `model_kwargs`, which passes it through to the provider API unchanged.

You enter both kinds the same way, and both load back as separate rows.

| Connection type | Parameters sent as-is |
|---|---|
| All | `model`, `temperature`, `max_tokens`, `top_p`, `timeout`, `max_retries`, `default_headers`, `model_kwargs` |
| OpenAI, OpenAI-compatible and every provider that uses the OpenAI wire format | `api_key`, `base_url`, `organization`, `reasoning`, `reasoning_effort`, `output_version`, `store`, `extra_body` |
| Groq | `api_key`, `groq_api_key`, `base_url`, `reasoning_format`, `reasoning_effort`, `output_version` |
| Hugging Face | `api_key`, `base_url` |

<Note>
  Passing a parameter through `model_kwargs` does not make the provider accept it. A parameter the provider API does not know still fails at inference, and the error comes from the provider.
</Note>

<Warning>
  Agents saved before this change may still carry an undefined parameter at the top level. On runtime 0.5.3 or later such an agent fails as soon as it answers. Open the agent and save it again to move the parameter into `model_kwargs`.
</Warning>
